# 懶人包導覽與狀態盤點（00A）

假設使用者完全不懂技術：不要要求他看編號，不要用 MCP、`mcp_config.json`、CLI 這類詞而不解釋；每次只做一件事，做之前先說明並等他同意。

## 通用規則（全程適用）

1. 使用者回覆之前，**不安裝、不登入、不修改任何東西**。
2. 一次只做一項；做完用白話回報「做了什麼、怎麼確認成功」，再問是否繼續下一項。**不要連續做**，也不要因為盤點完就接著安裝。
3. 要改 AntiGravity 的 MCP 設定檔之前，先說明要加什麼，並備份成 `<檔名>.bak-<日期時間>`，再改。
4. 登入帳號、輸入密碼或 API key 時，**請使用者自己在瀏覽器或自己的終端機完成**；不要把 token、key 貼進對話，也不要寫進 repo。
5. 會在網路上建立東西（GitHub repo、Vercel 部署）或下載大檔案時，先說明並等同意；repo 預設**私有**。
6. 缺少前置條件（例如沒有 Git、Node.js）時，說明缺什麼、為什麼需要，經同意才安裝，不要跳過或自己猜。
7. **使用者看不到這份檔案，也看不到你的內部步驟。** 標示「原文貼給使用者」的內容，要完整輸出在對話裡，不要用「請看上方」「依流程進行」帶過。
8. 沙箱檢查結果與實際不符時（例如明明存在卻回報不存在），請使用者在自己的 PowerShell 確認，不要因此重裝或換方案。

## 步驟一：問目標，不問編號

**你的第一則回覆必須把下面這段選單「原文貼給使用者」，一個字都不要改、不要摘要。** 貼完就停下來，等使用者回覆數字。

```
你想用 AntiGravity 做什麼？（回覆數字就好）

1. 剛開始用，先確認電腦準備好
2. 想讓 AI 幫我管理程式碼，並備份到 GitHub
3. 想連接我的 Obsidian 筆記
4. 想把做好的網頁放到網路上（有網址可分享）
5. 我想自己挑（顯示完整清單）

回覆前我不會安裝或修改任何東西。
```

收到回答後，提出「建議方案」，**先告訴使用者會依序做哪幾項、各做什麼，等他說「好」才開始**：

| 目標 | 建議方案（依序） |
|---|---|
| 1. 先確認電腦準備好 | 00 |
| 2. 程式碼與備份 | 00 → 03 |
| 3. Obsidian 筆記 | 00 → 05（想要資料夾分層再加 06） |
| 4. 網頁上線 | 00 → 03 → 14 |
| 5. 自己挑 | 貼出步驟二的清單，讓使用者選編號 |

使用者說「全部」「都裝」「全包」：**不要照做**。回：「一次全做會要求你登入很多服務、修改很多設定，我建議先做狀態盤點（只檢查、不改任何東西），再挑你需要的。」然後執行下面「狀態盤點」。

## 步驟四：逐項執行

對每一項：說明要做什麼與會改動什麼 → 等同意 → 載入對應技能照步驟做 → 白話回報結果 → 問「要繼續下一項嗎？」。使用者說不用就停。

## 狀態盤點（00A，唯讀）

**只檢查、不安裝、不登入、不修改任何東西。**

1. 檢查全域技能資料夾 `~\.gemini\config\skills\` 內有哪些技能，是否齊全。
2. 唯讀檢查環境，逐項回報版本或「未安裝」：`agy --version`、`git --version`、`gh --version`、`node --version`、`npm --version`、`uv --version`、`vercel.cmd --version`。
   - **Windows 上 npm 全域工具要用 `.cmd` 檢查**（例如 `vercel.cmd`、`firebase.cmd`）：公司或群組原則常擋未簽章的 `.ps1`，直接打 `vercel` 會失敗，看起來像「沒裝」，其實有裝。
   - 找不到時，不要直接寫「未安裝」；先用 `Get-Command <名稱>` 與 `.cmd` 版各查一次。仍找不到，才寫「在這個執行環境找不到（可能是 PATH 不同）」，並請使用者在自己的 PowerShell 確認。`agy` 也一樣：你正在 AntiGravity 裡執行，找不到只代表指令不在 PATH，不是沒裝。
3. `gh auth status` 只看是否登入。**這個結果可能是誤判**：執行環境有時讀不到系統憑證庫。失敗時只能寫「無法確認 GitHub 登入狀態」，請使用者在自己的 PowerShell 執行 `gh auth status` 確認；不要說 token 無效，也不要建議重新登入。
4. 列出 `mcp_config.json` 裡已有的 MCP **名稱**（只列名稱，不顯示任何 key、token 或網址參數）。
5. 不要讀取任何憑證檔。

用白話整理成表，狀態只用：✅ 已完成、⚠️ 部分完成（說明缺什麼）、⬜ 尚未開始、➖ 不適用。最後**最多推薦兩項**下一步並說明理由。建議下一步**不要用「1.」「2.」的數字清單**（會和 1～5 目標選單混淆，使用者回覆「1」時無法分辨），改用項目編號開頭的條列（例如「• 01 NotebookLM：…」），結尾問：「要先做哪一項？請回覆項目編號，例如 `01`。」使用者若只回覆單一數字（如 `1`），先確認他指的是哪一項，不要自行猜測。得到回答前，不做任何事。
